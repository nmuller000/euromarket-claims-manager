## Deviations and Corrections

| # | What happened | Cause | Correction |
|---|---------------|-------|------------|
| 1 | `Select-String` found nothing in the RMAN log | RMAN messages are in Spanish (`Recovery Manager terminado.`); log in ANSI | Pattern `ORA-|RMAN-[0-9]|Recovery Manager (complete|terminado)` |
| 2 | Recreating the auto-login with the keystore closed: `ORA-46634` with an empty location | The auto-login is created from an **open** keystore | Recovery order: open with the password, then create the auto-login (`08`) |
| 3 | Opening with the password: `ORA-28353`; `orapki` confirmed *incorrect password* | The password stored in the password manager did not match the one typed when the keystore was created (hidden input; the password manager clears the clipboard after 10 s) | Keys copied with `MERGE KEYSTORE` from the working auto-login into a new keystore with a verified password, then swapped (`09a`, `09b`); **same master keys, backups still valid**. Rule: verify the stored password with `orapki` right after creating a keystore (`05`) |
| 4 | `MERGE` into the keystore created by `orapki`: `ORA-46626` | `orapki` leaves the file readable by its creator only; the database runs as `NT SERVICE\OracleServiceFREE` | `icacls … /reset` on the new `ewallet.p12` (`09a`) |
| 5 | ORDS kept running during restarts | Not stopped before the scripts | No damage (`SHUTDOWN IMMEDIATE` ends sessions); ORDS restarted; restart scripts now ask for confirmation |
| 6 | Backup of the target keystore from `MERGE … WITH BACKUP` has 225 bytes | It is a copy of the **empty** target before the merge | Only `ewallet.p12` after the merge is kept as key copy |
